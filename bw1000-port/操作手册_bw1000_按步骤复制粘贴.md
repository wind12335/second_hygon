> **怎么用这份手册**：从第 0 步开始按顺序往下走。每一步 = 一段可以整体复制粘贴的
> 命令 + "预期看到什么" + "出错了怎么办"。**所有命令都在解压出的 `bw1000_port/`
> 目录里执行**（第 0 步会 cd 进去）。
> 遇到任何手册没写的情况：把**完整终端输出截图或复制**发回来，不要自行改代码绕过。

## 第 2 步：编译（架构名从体检报告里抄）

把下面命令里的 `gfx9XX` 换成报告 SUMMARY 里 `gfx_arch=` 显示的名字：

```bash
make clean
make ARCH=gfx9XX COV=4 2>&1 | tee build.log
ls -la ag_gemm_phaseb
```

**预期**：编译几十秒到几分钟，最后 `ls` 能看到 `ag_gemm_phaseb` 可执行文件，
`build.log` 里没有 `error`。

❌ 如果报错：
- `hipcc: command not found` → 先 `export PATH=/opt/dtk/bin:/opt/mpi/bin:$PATH` 再重试；
- 找不到 `dushmem.h` / `libdushmem_device.so` → 说明 DUSHMEM 装在别的路径，
  把报告里 "DTK 目录" 一节的输出发回来，我改 Makefile 路径；
- `-mcode-object-version` 不认识 → 去掉再试：`make ARCH=gfx9XX COV=3` 或直接
  `make ARCH=gfx9XX` 前先 `sed -i 's/-mcode-object-version=$(COV)//' Makefile`；
- 其他任何报错 → 把 `build.log` 发回来。

## 第 3 步：冒烟（约 10–15 分钟，2048/q8 × 全路径 × 1 次重复）

```bash
nohup bash run_phaseb_bw.sh smoke > run_smoke.log 2>&1 &
echo "smoke 启动, 日志: run_smoke.log"
```

看进度（随时可执行，Ctrl+C 退出查看不影响后台）：

```bash
tail -f run_smoke.log
```

**预期**：一行一个 case，形如 `[ ok ] case001_comm_C0_DEFAULT_N2048_q8_rep1`，
最后一行是 `== phaseb(bw1000) smoke np=4 complete: XX cases, 0 failed ==`。

判断是否跑完：

```bash
tail -2 run_smoke.log
```

**→ 跑完后把最后 5 行发回来（或直接做第 6 步打包发回）。有 FAIL 也可以继续，
先告诉我 FAIL 了几个、哪些路径。**

❌ 常见错误：
- `mpirun ... unrecognized option` 或 coll 报错 → 告诉我，我给一条去掉 `-mca coll
  ^hcoll` 的替代命令；
- `DUSHMEM init failed` / d 族路径 FAIL 但 r 族全过 → 说明 DUSHMEM 环境有问题，
  r 族数据仍有效，把失败 case 的 `stdout_stderr.log` 发回来。

## 第 4 步：正式批 · np=4 对照批（约 2–4 小时，与海光 K500 4 卡同口径，必跑）

```bash
nohup bash run_phaseb_bw.sh formal > run_formal_np4.log 2>&1 &
echo "formal np=4 启动"
```

日常三个命令（想到就看一眼）：

```bash
# 进度（按 Ctrl+C 退出）
tail -f run_formal_np4.log
# 目前完成了多少、失败了多少
grep -c '\[ ok \]' run_formal_np4.log; grep -c 'FAIL' run_formal_np4.log
# 是否跑完（出现 complete 即结束）
grep 'complete:' run_formal_np4.log
```

**纪律（很重要）**：
- 运行期间**不要**重新 `make`、**不要**在这台机上跑其他 GPU 任务；
- 结果目录带时间戳，断掉也不会覆盖数据；中断了直接告诉我，**不要删目录**。

**预期**：最后一行 `== phaseb(bw1000) formal np=4 complete: ~700 cases, 0 failed ==`
（允许少量 FAIL；>5 个或成片 FAIL 就停下来发日志给我）。

## 第 5 步：正式批 · np=8 规模批（约 2–5 小时，8 卡满配，强烈建议跑）

```bash
NP=8 nohup bash run_phaseb_bw.sh formal > run_formal_np8.log 2>&1 &
echo "formal np=8 启动"
```

查看命令与第 4 步相同（把 `run_formal_np4.log` 换成 `run_formal_np8.log`）。

> 为什么两批都要：np=4 与 K500 四卡**同口径**，是跨基座对照的主数据；
> np=8 是新增的规模轴（每卡收 7 份数据、计算量翻倍），测传感器规则在
> rank 数变化下是否守恒。时间紧就先保证 np=4。

## 附录 A：中断 / 断电 / 出错怎么办

1. **批跑到一半断了**：什么都不要删。结果根在 `results/bw1000_8gpu/
   phaseb_<mode>_np<N>_<时间戳>/`，已完成的 case 都在 `cases/` 里，部分数据
   依然可用。重新跑会生成**新时间戳目录**，不会覆盖。把情况告诉我即可。
2. **某个 case 超时 FAIL**：不用管，runner 会继续跑下一个；最后统计在
   `run_metadata.txt` 的 `failed_cases`。
3. **想中途停掉**：`pkill -f ag_gemm_phaseb`（会杀掉当前 case 的 mpirun），
   已完成的数据保留。

## 附录 B：如果体检报告显示 DUSHMEM 不可用（dushmem_present=NO）

d 族路径（fc/dc/d0/ds/d1/d1w）跑不了，但 r 族（RCCL）全套仍可跑——反转与
选择器的主结论都在 r 族 + comm 上。用这条命令启动：

```bash
PHASEB_PATHS="comm gemm r0 rs r1" nohup bash run_phaseb_bw.sh formal > run_formal_np4.log 2>&1 &
```

smoke 同理加前缀 `PHASEB_PATHS="comm gemm r0 rs r1" `。

## 附录 C：结果里都有什么（回传后我会看的东西）

- 每个 case：`case.json`（结果摘要）、`raw_global_samples.csv`（逐次迭代计时）、
  `manifest.csv`（参数）、`stdout_stderr.log`、`command.txt`（精确复现命令）；

- `run_metadata.txt`（起止时间、case 数、失败数、二进制哈希）；
- `platform/platform_facts.txt`（GPU/编译器事实）。
