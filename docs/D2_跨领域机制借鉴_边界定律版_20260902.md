## 0. 今晚的新证据（借鉴的靶子）

1. **边界定律**（P14 三 HIT 定量版）：d1 反模式的惩罚由两个正交因子决定——
   **同步点数 q 抬高边界曲线的位置，片计算量 N/q 决定曲线斜率**
   （q8：64列 +40.0 / 256列 +29.5 / 512列 −21.0 反转；q16：128列 +69.9 / 256列 +40.8 不反转）。
2. **C4 协议族结构性串行化**：逐片 credit/槽位流控把 producer 绑在 consumer 上一片 GEMM 之后；
   wait placement 修复（d1w）无效，全 10 格与 d1 同步。与 4090 侧发现 F（有界前瞻窗口 w=2/4
   比串行慢 10–30%、空闲-爆发锁步）两端独立撞同一机理。
3. **家族轴新检查（本文件 §4，10 格）**：DUSHMEM dc 在 **N4096/q2（−14.9%）与 N4096/q4（−8.7%）
   反超 RCCL r1**——通信主导区存在家族级反转，两级选择器（family×config）可行性成立。

## 1. 机理叙述层：三个"给现象正名"的锚点

### 1.1 Parks 1995 人工死锁（KPN 有界调度）↔ C4 结构性串行化 ★最强锚点

- **来源领域**：嵌入式/数据流计算。Kahn 进程网络（KPN）语义上天然无死锁，但**给通道加有界缓冲后，
  会制造"原始语义里不存在的依赖"——人工死锁（artificial deadlock）**。Parks 算法：遇人工死锁就把
  最小的缓冲加一，直到有界执行可行。SDF（同步数据流）更有可判定的有界性/死锁分析（平衡方程）。
- **我方对应**：d1/ds/d1w 的 slot 深度（window_mult）就是 KPN 通道缓冲。槽位深度=1（逐片 credit
  门控）时，"producer 等consumer 释放槽位"这条依赖**在数学任务图里不存在**（数据只被写一次、
  读一次，无真依赖）——是协议制造的人工依赖。d1w 无效（等待挪流不改变依赖结构）恰是
  "病理在缓冲深度不在等待位置"的 Parks 式判据。
- **怎么用**：论文 §5.4 直接写"结构性串行化 = 有界缓冲引入的人工依赖（Parks 1995 意义上的
  artificial deadlock 的时变版：不死锁但退化为锁步）"；**d2 window_mult 深槽位实验 = Parks 的
  "递增缓冲"操作化**——预注册 P15：槽位深度 2/4/8 时 d1 惩罚应单调收窄，且收窄速率由 N/q
  （片计算时长）决定（深槽位只要 ≥ 消费延迟/生产延迟比即可近似无人工依赖——这给出**边界定律的
  解析形式雏形**：临界槽位深度 w* ≈ ceil(GEMM_片时延 / 传输_片时延)，N/q 越大 w* 越小）。
- **引用**：T. M. Parks, *Bounded Scheduling of Process Networks*, UCB/ERL-95-105, 1995（411 引）；
  M. Geilen, *Requirements on the Execution of Kahn Process Networks*（缓冲过小→人工死锁的明确表述）；
  Lee & Messerschmitt, SDF 平衡方程（1987）。

### 1.2 convoy effect（FCFS 护航效应）↔ 空闲-爆发锁步

- **来源领域**：OS 调度（Silberschatz 教科书）：FCFS 下短任务排队长任务后面，整体平均响应时间
  恶化；进程因资源相似而**互相同步化**（lockstep）。
- **我方对应**：4090 侧发现 F 的"credit 等待→空闲-爆发锁步"和我们 F6 release 曲线的阶梯状
  突发，就是通信流被 credit 门控后的护航效应。GPU 调度综述（2025）明确把 FCFS convoy effect
  搬进 GPU 任务调度语境；NVIDIA 开发者论坛有"重叠导致 GEMM 严重退化的 tail effect"孤立报告
  （工业界民间证据，可作脚注）。
- **怎么用**：给现象一个 40 年历史的标准名字，避免被审稿人当成"我们造词"。§5.4 一句话即可：
  "空闲-爆发锁步是经典护航效应在流式通信协议上的再现"。
- **引用**：Silberschatz et al., *Operating System Concepts*（convoy effect）；
  *Algorithmic Techniques for GPU Scheduling: A Comprehensive Survey*（2025，GPU 语境）。

### 1.3 完成语义开销的先行测量（MPI RMA 通知代价）↔ release 语义梯子

- **来源领域**：MPI 单边通信。Sergent et al. 2019 实测 Put/Flush/Put 通知协议的额外往返开销；
  Schuchart et al. 2021（Quo Vadis MPI RMA）系统分析 flush/完成通知低效；MPI Forum 讨论中明确
  "RMA 完成可能需要全网往返，短通信间隔下开销显著"。
- **我方对应**：Phase A 的"本地完成≠可消费"（release 比 stream complete 晚 10–23µs）与
  release→GEMM 延迟梯子（d1 5.4µs / d0 16.2µs / r1 10–47µs）是同一问题在 GPU 单边通信
  （DUSHMEM/NVSHMEM）上的版本。
- **怎么用**：Related Work 定位——"完成语义代价在 MPI RMA 已有系统研究（Sergent/Schuchart），
  我们把它推进到 GPU 流式重叠场景并证明它足以反转策略排序"。
- **引用**：G. Sergent et al., *Efficient Notifications for MPI One-Sided Applications*, 2019；
  J. Schuchart et al., *Quo Vadis MPI RMA?*, 2021（arXiv:2111.08142）。

## 2. 边界定律的数学形式层

### 2.1 α-β / LogGP 模型 + "重叠下失效"的公认批判 ★定位句

- **来源领域**：并行通信模型。α-β 模型：T = α·k + β·m（k 段消息）；LogGP 补充单消息在飞。
  **MLSys Handbook（vol2 collective communication 章）明确指出：α-β 假设处理器在通信期间空闲，
  在通信与计算重叠的流水线系统里失效**。
- **我方对应**：边界定律正是重叠状态下对 α-β 的经验修正——反模式惩罚 ≈ q·α_sync（同步点项，
  抬位置）− 重叠回收项（随 N/q 片计算增大而增大，定斜率）。我们不是提出新模型，而是**用 11 格
  同二进制数据给出"α-β 何时失效、失效多少"的可测边界**。
- **怎么用**：§3（模型）/§6（Related Work）写：HiPIPE（IWQoS 2025）用 α-β 调自适应分块、
  HeteCCL（NSDI'26）用 α-β 做异构链路合成——都在**孤立通信**假设下用模型；我们的边界定律是
  e2e 重叠场景下同一模型族的**失效边界经验律**，与其互补。
- **引用**：HiPIPE（IWQoS 2025, DOI 10.1109/IWQoS65803.2025.11143446）；HeteCCL（NSDI 2026）；
  MLSys Handbook vol.2 collective communication 章；LogGP（Alexandrov et al. 1995）。

### 2.2 Little's Law（可选轻提）

边界条件解析式备用：WIP = λ·W。流式协议在制品（在飞分片数 = 槽位深度）× 消费速率 = 稳态
吞吐；槽位深度 < λ·W 时管道断流。这给 w* ≈ ceil(生产时延/消费时延) 同一结论的第二条独立
推导路线。论文里作为一句话直觉，不展开。

## 3. 修复设计空间层（d2/d3 的跨领域出身）

### 3.1 Smith 预估器 / 死区补偿（网络化控制系统 NCS）→ d2' credit 预释放

- **来源领域**：控制理论。Smith 预估器用过程模型把死区从反馈环里"预测掉"；NCS 文献把它
  用于网络时延补偿（Filtered Smith predictor 处理随机网络时延，2025-2026 仍在活跃）。
- **我方对应**：credit 门控的死区 = consumer 完成信号传回 producer 的环路延迟。d2' 方案：
  producer 不等实际完成信号，而按"消费速率模型"**预释放**槽位（Smith 式前向预测）。
  模型误差风险 ↔ Smith 预估器对模型失配敏感（控制文献公认缺陷）——需要双缓冲 + 失配回退
  （写新槽前查目标 epoch 是否真的已消费，失配则退回门控模式）。
- **定位**：这是 d2（单纯加深槽位）的进阶版，列为 future work 或快速原型；与 d2 共享同一
  预注册（P15 的 w* 预测公式本身就是"消费速率模型"的第一次标定）。
- **引用**：Normey-Rico & Camacho 死区补偿综述（Frontiers in Control Engineering 2022）；
  Predictor-Based Compensators for NCS（arXiv:2506.23421）。

### 3.2 Tomasulo 记分板 → d3 乱序消费 ★空白证据

- **来源领域**：乱序处理器。记分板/Tomasulo 让就绪指令乱序执行，只受真数据依赖约束。
- **我方对应**：分片到达顺序 ≠ 最优消费顺序。d3 方案：consumer 维护"列块就绪位图"（记分板），
  GEMM 对就绪块乱序发射（通信完成顺序天然乱序：近端 rank 先到）。**搜索确认：Tomasulo/记分板
  到"网络消息乱序消费"没有先例桥接**（搜索原话："no results directly bridged these concepts"）——
  这是空白，但工作量大（GEMM 调度器改造），论文定位为 future work 一段，不做实现。
- **引用**：Tomasulo 1967（经典）；无需更多——空白本身就是卖点。

## 4. 选择器层（B3 v2 与两级选择器）

### 4.1 重尾 bandit（median-of-means / Catoni / 截断估计）→ B3 v2 的鲁棒特征

- **来源领域**：在线学习。重尾奖励下的 best-arm identification：median-of-means、Catoni 估计器、
  截断均值都已被证明比样本均值鲁棒（Bubeck 2013 奠基；Kagrecha et al. 2017 直接做 robust BAI；
  ICML 2025 有 Catoni contextual bandits）。
- **我方对应**：4090 侧时钟漂移 3–10%（同 run 比较红线）+ 我方 N4096/q16 d1 rep 波动 ~16%
  （P14d 的幅度 MISS 就栽在这）——选择器特征若用均值口径，正好落进重尾陷阱。4090 侧 M6
  建议"加 R_0 分位数特征"与我们 DX 格"ratio 带外处理"独立同判。
- **怎么用**：B3 v2 = 现有规则 + ①特征估计器从均值换成 median-of-means（实现 5 行）；
  ②加 R_0 P90/P99 分位特征；③ratio>1.35 带外格走保守基线（DX 教训）。
- **引用**：Bubeck et al. 2013（Bandits with Heavy Tail）；Kagrecha et al. 2017（robust BAI）；
  Zhong et al. NeurIPS 2021（mean of medians）。

### 4.2 ACCLAiM（TPDS 2026）定位引用 + 两级选择器

- ACCLAiM：ML 代理模型选 collective **算法**（isolated 场景，替代 OpenMPI/MPICH 启发式决策）。
  与我们正交：他们不选**重叠策略族**、不进入 e2e 场景、不涉及 release 语义。引用后明确三差：
  ①isolated→e2e；②单轴算法→family×config 两级；③静态模型→release 感知特征。
- **两级选择器（今晚新证据支撑）**：家族轴 10 格检查（§5 表）发现 dc 仅在 N4096/q2、q4 赢 r1
  （通信主导区）——**家族选择有真实收益格，两级选择器（先族后配置）不是空想**。粗判据方向：
  通信主导（小 q 大 N）→ DUSHMEM 直采族；计算/平衡区 → RCCL 族 + 现有 B3。
- **引用**：Wilkins et al., ACCLAiM（TPDS 2026）；Hunold & Bhatele（SC 2020，MPI 预测）。

## 6. 撞车复扫结论（2026-09-02 深夜轮）

| 近邻工作 | 做了什么 | 与我们的差 |
| --- | --- | --- |
| HiPIPE（IWQoS 2025） | α-β 模型自适应 chunk 流水线调度 | 调 chunk 尺寸；不做策略族选择、无边界定律、无 release 语义 |
| HeteCCL（NSDI 2026） | α-β 驱动的异构 collective 合成 | isolated 合成；不做 e2e 重叠场景 |
| TokenWeave（MLSys 2026 oral） | TP 推理 AllGather 重叠，chunk-prefill 权衡 | 推理场景、单一策略优化；无策略间反转 |
| AutoOverlap（2025） | 编译器+运行时自适应 chunk 细粒度重叠 | chunk 轴自动调优；不跨协议族 |
| ACCLAiM（TPDS 2026） | ML 选 collective 算法 | isolated、单轴（算法）、无 release 特征 |
| PIMnet（2025） | credit 流控 vs PIM 调度对比（collective） | 硬件网络层；不涉及 GPU 流/策略选择 |
| Sergent 2019 / Schuchart 2021 | MPI RMA 完成通知开销 | CPU MPI 语义优化；无策略排序反转结论 |
| FLUX / ACE / Megatron overlap | 重叠 kernel/调度工程 | 单策略工程优化；无边界/选择问题陈述 |

**四大空白依然成立**：①e2e 重叠场景的策略族间反转与边界定律；②release 语义作为策略排序的
一阶变量（梯子数据）；③结构性串行化的人工依赖定名（Parks 桥接是新的加分叙述）；④两级
（family×config）release 感知选择器。**无新威胁。**

## 7. 落地清单（按优先级）

1. **P15 预注册 + 补批**（明天首选，~75 case）：①d2 window_mult ∈ {2,4}（d1 深槽位，验 w*

   α-β 失效批判引用（§3 模型节）。
