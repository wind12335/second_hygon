⚠ 对 REPORT.md 原结论的修正(2026-10-10,本页数据发现): 原报告推断"worker-0 早到长等、worker-1 晚到少等"——方向反了。依据:①16 rank 的 AR 结束时刻高度同步 (锚定残差 p50=3µs / p90=19.7µs),而 dur = 结束 − 到达 ⇒ 时长越长 = 到得越早;②据此重排:worker-1 的 rank kernel 时长普遍更长 ⇒ 到得更早且整队紧密;worker-0 内部到达散布 295µs(中位),含绝大多数全局最晚者。 ③原口径把"节点内最小时长"当走线(worker-0 均值 193µs),但全局最晚者多在 worker-0 ⇒ worker-1 的最小时长(437µs)里 大头是等待。修正后:真走线 = 全局最小时长,均值 92µs,总量 3.8s(12.6% 墙钟);真等待 = 16.8s(55.4% 墙钟,单 rank 视角) ——等待池比原口径(45%)更大。"AR 名义占 ~68-75%,其中约 4/5 是等待"的论文表述据此更新。
方法口径(与文档 §1.5 一致并细化): ① 同节点 8 rank 共享主机时钟,节点内时刻直接可比;跨节点时钟独立,用"AR 结束时刻近似同步"锚定 (offset = 中位数 7.6µs,残差 p90 = 19.7µs ≪ δ 中位 534µs,故锚定可靠); ② 真走线 W = 每个集合全局 16 rank 的最小时长(全局最晚到达者的 kernel ≈ 纯协议+搬运,上界的紧估计); ③ 真等待 = dur − W;④ 自旋模型互验:节点内 (dur − dur_min) 与 (最晚 ts − ts) 两种独立算法之差 p50 = 2.4µs ✓; ⑤ 数据由 build_07_arrival_data.py 从 analysis/rank_*.json 的逐事件序列自动生成,可复算。
