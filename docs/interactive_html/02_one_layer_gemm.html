tile 量化:GEMM 的 M 方向被切成 64 行一块(kernel 名 Cijk_Ailk_Bljk_…_MT64x16x128 的 64 即 tile 高)
M=32 时连一个 tile 都填不满:tile 里 64 行只有 32 行是真数据(绿),其余是空转(红)—— 这就是"decode 计算塌缩"的微观形态:GEMM 时间不再随 M 线性下降,而是被 tile 地板托住。 M 越大(拖到 8000)tile 越满,GEMM 越接近线性扩展 —— prefill 与 decode 的效率差就从这里开始。
