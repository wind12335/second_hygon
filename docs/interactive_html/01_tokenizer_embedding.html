① 预处理与 Embedding —— 词表并行查表 + AllReduce 求和(§10)

← 返回导航 | 流程:文本 → 分词(token id)→ 各 rank 查自己那 1/TP 词表 → AllReduce 求和 → 完整输入 [M, 8192]

输入文本(分词为示意:按字符伪随机映射到 0–128255;真实 Llama-3 用 BPE 子词,词表同为 128256):
张量并行度 TP = 16(每 rank 持有 行词表)
每个 rank 的卡片:持有行区间 + 本句命中哪些 token。命中为 0 的 rank 交"全零"答卷。
按"① 分词"开始
AllReduce 完成:16 份"各自查了一部分、其余为零"的矩阵相加 = 完整的 [M, 8192] 输入。 这就是一步里第 161 个 AllReduce(前 160 个 = 80 层 × 2;实测 41,538 AR = 258 step × 161,严丝合缝)。
为什么查表也要通信?因为 id→向量的映射被切成了 16 段分散在各卡——这是"切权重"的代价之一: 不只 GEMM 产生部分和,查表也会。颜色即贡献来源 rank。
