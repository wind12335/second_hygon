# D. 跨领域机制借鉴：给"释放感知策略选择器"找成熟设计范式

日期：2026-09-02
服务对象：第二篇论文 C3 贡献（release-aware selector）的设计与叙事。
背景：用户指示"必要时可以拿其他领域的算法或机制拿过来借鉴"。本备忘录把六个领域的成熟机制映射到我们的问题上，回答两个问题：(1) 选择器该长什么样才能既简单又站得住；(2) 论文里怎么借这些领域的"正统性"防 reviewer 的三连问（为什么可信/为什么实用/为什么不会选错）。

## 0. 我们的选择器问题重述（一句话版）

给定工况 (N, q) 与可廉价观测的特征 r = t_comm/t_gemm（isolated 微基准即可得，不需要跑全 e2e 矩阵），从策略池 {r0, rs, r1, d0, ds, d1, d1w} 中选端到端最优的一条，且跨两个基座（RCCL/DUSHMEM、海光/NVIDIA）都要工作。

问题的三个本质特征，决定该借什么：
1. **最优策略随工况分段切换，边界非单调**（资源轴反转 + 结构轴翻转）→ 需要控制论的"增益调度"范式；
2. **端到端标签昂贵（要跑完整 pipeline），但特征便宜**→ 需要数据库"代价模型外推"与编译器"安装时标定"的方法论；
3. **选错有代价（regret），且部署环境与标定环境有漂移** → 需要在线学习（bandit）与安全回退（AIMD 思想）。

## 1. M1 增益调度（Gain Scheduling，控制论）

- **原领域**：飞行控制。增益随高度/马赫数等"调度变量"查表切换，表间插值，调度变量变化慢于被控对象动态时可保证稳定。
- **映射**：策略 p ↔ 控制器增益；(N, q, r) ↔ 调度变量（马赫数/攻角）；反转边界（C2 赢家随 N 变化、d1/d0 赢家随 q 翻转）↔ 增益切换边界；选择表 ↔ gain schedule 表。
- **可借鉴的三个具体设计**：
  1. **慢调度假设的对应物**：增益调度要求调度变量慢于系统动态——我们的对应假设是"同一次训练运行内 (N,q) 不频繁变化"，这解释了为什么**离线标定 + 运行时查表**够用，不需要每步在线决策。这是对"为什么不用强化学习"的标准答复。
  2. **切换边界用滞回（hysteresis）而非硬阈值**：飞行器在边界附近抖动会乒乓切换。我们的选择器在反转边界格（如 N2048/q8 附近 ±5%）应设置死区：预测置信度低或两策略差距 < 阈值（如 3%）时默认选保守策略（r0/C0 默认配置）。**这直接把"边界格选错"从缺陷转化为设计约束**。
  3. **调度表随基座重标定**：换基座=换飞行器型号，表要重标但**结构（表的维度和查表逻辑）不变**。这就是我们"双基座能力抽象 B + 同一选择器结构"的叙事根基。
- **落点**：论文 §Design（选择器框架图）+ §Discussion（threats 的答复）。

## 2. M2 代价模型外推（Cost-Based Query Optimization，数据库）

- **原领域**：DB 查询优化器（System R 谷歌以来 40 年）。三组件：基数估计（cardinality estimation）→ 代价模型 → 计划枚举。离线标定代价系数，查询时外推。
- **映射**（同构到令人舒适的程度）：

  | 数据库 | 我们 |
  |---|---|
  | 基数估计 | 基座能力向量 B（comm/fc/dc 的 isolated t_done） |
  | 代价模型（算子代价公式） | stretch 模型：e2e ≈ f(传输, GEMM 节奏, 释放语义档位) |
  | 计划枚举 | 策略池 {r0, rs, r1, d0, ds, d1, d1w} |
  | leave-one-workload-out 评估 | 我们的 LOO（leave-one-cell-out）评估 |
  | "优化器误差 → 选次优计划" | regret 指标（预测策略 e2e 超出最优的百分比） |

- **可借鉴**：
  1. **评估方法论的先例**：DB 社区几十年来就用"预测 top-1 精度 + regret"评估代价模型，我们沿用这套指标可免于自创指标的解释成本。
  2. **"代价模型只需要排序对，不需要绝对值准"**：DB 的著名教训——基数估计差 10 倍但计划选择常常仍对。对我们的启示：stretch 模型的目标函数应该是**格内排序的正确性**而非 e2e 绝对值的拟合精度。这降低了对模型复杂度的要求（论文里一个简单规则就够）。
  3. ** Learned cardinality 的分寸**：DB 社区 2015-2021 证明了 learned cost model 可行但部署受漂移困扰，最终生产系统仍用简单模型+重标定。这支持我们"简单规则 + 每机标定"而非"深度模型"的选择。
- **落点**：论文 §Evaluation（LOO 协议）+ §Discussion（为什么简单模型够）。

## 3. M3 上下文赌博机（Contextual Bandit，BanditWare arXiv 2506.13730）

- **原领域**：在线学习。每轮观察上下文，从臂集合选一个，只观察所选臂的回报。
- **映射**：上下文 = (N, q, r)；臂 = 策略池；回报 = 该次运行的 e2e（或其倒数）。
- **可借鉴**：
  1. **冷启动 + 在线精化的两层结构**：BanditWare（2025，GPU 硬件配置的 bandit 选择）正是"离线先验 + 在线探索"结构。我们的部署故事可以是：离线标定表做先验（ exploitation），真实训练任务的间歇（如 eval 阶段）用 ε-greedy 或 UCB 探索边界格。**这是论文 future work / 扩展性的现成叙事**。
  2. **regret 语言直接复用**：bandit 的 regret 定义与我们的 LOO regret 一致，跨文献可比。
  3. **分寸**：不把 bandit 做成本文贡献（那是第三篇的事），只在 Discussion 引用，说明选择表可以无缝升级为在线选择器——**堵住"离线表过时怎么办"的 reviewer 问题**。
- **落点**：论文 §Discussion + Related Work。

## 4. M4 安装时标定（FFTW planner / ATLAS，HPC 自家传统）

- **原领域**：数值库。FFTW 的 planner 对每台机器离线跑搜索生成"plan"；ATLAS 安装时标定 BLAS 参数。
- **可借鉴**：
  1. **合法性先例**：HPC 社区完全接受"每机一次的离线标定成本"，FFTW/ATLAS 装机即标定 20 多年。我们的选择表标定（~2h 的 formal 矩阵）在同一传统里，**实用性无需辩护**。
  2. **plan 的持久化与复用**：FFTW 把 plan 缓存（wisdom），可导出复用。我们的对应物：标定表随 manifest/sha256 存档，同型号机器群可共享（海光同构集群特别成立）。
  3. **标定的分级**：FFTW 有 ESTIMATE（快而糙）/MEASURE（慢而准）/PATIENT（ exhaustive）。我们的对应：smoke（单 rep）/formal（5 reps）已经是这个分级——论文里可以明说标定预算可调。
- **落点**：论文 §Design（标定协议）+ Discussion。

## 5. M5 垂直切换（异构无线网络的多准则选择 + 乒乓避免）

- **原领域**：4G/5G/WiFi 异构网络中选择接入网。多准则（RSS/带宽/代价/能耗）+ 切换决策，核心痛点是**乒乓效应**（边界上来回切换，切换本身有代价）。
- **映射**：基座（RCCL vs DUSHMEM）↔ 接入网；切换代价 ↔ 策略切换的缓存/状态重建；乒乓 ↔ 边界工况下策略抖动。
- **可借鉴**：
  1. **多准则决策的标准做法**（AHP/TOPSIS/简单加权）：我们的选择其实是三准则（传输能力 B、重叠可恢复性、语义代价），垂直切换文献提供了"多准则怎么合成一个决策"的成熟做法——但对我们目前规模（7 策略 2 基座），简单规则 + 边界死区已经够，MCDM 只在 Related Work 提。
  2. **驻留定时器（dwell timer）思想**：切换决策要连续满足 K 次才执行。对应：选择器输出要在连续若干个 slice/run 稳定才切换策略——防止测量噪声驱动抖动。与我们 5/5 rep 方向一致性准则同构，可作为运行时版。
- **落点**：Related Work（选择问题的谱系定位）+ 选择器的稳定性设计。

## 6. M6 安全回退（AIMD，拥塞控制）

- **原领域**：TCP 拥塞控制。激进探索、探测到丢失立刻乘性回退到保守区。
- **可借鉴**：
  1. **safe-by-default 结构**：选择器任何组件失效（特征测不到、表里没这个格、模型输出 NaN）→ 一律回退 r0 + C0 默认配置（我们数据里 r0 从不灾难性差，最差格 regret 有界）。论文里把这条写成设计原则，配"回退路径覆盖率"说明。
  2. **保守区可证**：我们已有数据证明默认配置的 regret 上界（LOO 表的 worst regret 就是这个数）——这就是 AIMD "回退到哪"的定量答案。
- **落点**：论文 §Design（一条段落+一个伪代码分支）。

## 8. 撞车复扫结论（2026-09-02 下午，3 次定向搜索）

1. **BanditWare（arXiv 2506.13730, 2025）**：contextual bandit 选 GPU 硬件配置——最接近的先例，但其上下文是任务特征选**硬件**，不是通信**语义/策略**；且不做反转机理。引用而不撞车。
2. **Collective Communication for Distributed LLM Systems（arXiv 2608.15118, 2026 综述）**：三层 taxonomy（planning/execution/coordination）。**作为 Related Work 的锚点**：它做分类学、不做选择机制，可在其"coordination layer"叙述后指出"缺少释放语义感知的选择准则"——正好把我们的空白放进现成框架的缺口里。
3. NCCL vs NVSHMEM 相关讨论：仍是 Demystifying NVSHMEM（2606.05951，ETH+NVIDIA，已列头号风险）、NCCL GitHub issue #679、HOTI tutorial 等已知项。**无新占坑**。
4. 结合上午的分报告（Lagom 2602.20656 占资源轴前半句、DeFT 2503.16815 已核实无撞车）：四大空白依然成立——**语义结构轴 / 语义强度×重叠收益曲线 / 双基座能力抽象+选择器 / DUSHMEM 英文论文为零**。

## 9. 对当前实验计划的反馈（机制视角检查）

- d1w（wait placement 变体）正好落在 M1 的"设计变量"逻辑里：它不是又一个策略，而是**语义轴上的一个刻度**——论文里应作为"选择空间的结构化扩展"呈现，而非 ad hoc 变体。
- dsfix 补测后，selector 的 P2 规则应在 d1w 数据到位后重拟合（P2 的阈值 2.0/0.5 是拍的，formal 全矩阵到手后用数据重定）。
- LOO 的 worst regret（回退上界）应在论文里和 M6 的 safe-default 一起讲——单个数字两种用法。
