## 一、今天定稿的四个结果

### 1. 反转图谱（资源轴）+ ★平衡律
- 同一二进制、11 条路径、双协议栈（RCCL + DUSHMEM）、(N,q) 十格全矩阵、5 rep 全 SIG。
- **isolated 层**：调优配置 C2（Ring/Simple/8 通道）十格全快 +0.7~3.2% —— 带宽排名十格全指向 C2。
- **e2e 层**：N2048/q8 与 q16 两格翻负（−5.49% / −5.37%）——**恰好**是"通信/计算比值≈1（双资源饱和）∧ 切片深（q≥8）∧ isolated 优势薄（≤1.65%）"的格子。
- **带内全列**（N2048，比值恒 ≈1.2）：+5.65 → +1.69 → −5.49 → −5.37（q=2/4/8/16）——
  阈值在 q=8，q=16 饱和。**反转=有界共振带，不是单调曲面**。
- 机理解释：平衡点双资源同时饱和，C2 的多通道竞争从 GEMM 关键路径偷时间；
  通信主导时带宽优势正常传导（+5%），计算主导时被 GEMM 阴影淹没（回弹 +1.8%）。

### 2. 双轴反转（结构轴）：q=8 全列
- DUSHMEM 家族内："重叠"路径 d1（put-signal 逐片释放）vs 串行 d0（fcollect）：
  - q=2/4：d1 赢 +21~30%（三个 N 全部）
  - **q=8：d1 输 −45.4% / −41.1% / −19.4%（N=512/2048/4096 全列，5/5 SIG）**
- 机理由 per-slice release 曲线钉死：d1 的 consumer 等待放在承载数据的 compute_stream
  上 → **首个 release 被推迟到全部传输完成之后**（14.4ms vs wait-stream 放置的 1.4ms
  @N512/q8）——"重叠"路径结构性地无法重叠。等待放置是此前文献没拆过的变量。
- 修复变体 d1w（等待挪到 wait_stream + 事件桥）已实现，补测批正在跑（预计明早出）。
