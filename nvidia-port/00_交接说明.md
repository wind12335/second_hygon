# NVIDIA 侧（RTX 4090 ×4）交接说明

你（LYC）在 4090 机器上执行，我在 DCU 侧远程配合。**每一步只做一件事，卡住了就把对应产物发回来，我来改**。

## 交付物清单

| 文件 | 作用 |
|---|---|
| `ag_gemm_phaseb_nv.cpp` | 10 路径统一基准（CUDA/NCCL/NVSHMEM/cuBLAS 版，口径与海光版完全一致）|
| `Makefile` | `make` 一键编译（需 nvcc sm_89 + NCCL + NVSHMEM + cuBLAS + MPI）|
| `run_phaseb_nv.sh {smoke\|formal}` | 运行器：时间戳结果根目录、防覆盖、逐 case 落盘 command.txt / stdout_stderr.log / exit_status.txt、平台档案、源码快照 |
| `env_check.sh` | **第一步**：机器形态+工具链探测 → `env_check_report.txt` |
| `p2p_probe.cu` | 4090 互联形态实测（P2P 矩阵 + 带宽矩阵），env_check 自动编译运行 |
| `collect_results.sh` | **最后一步**：把要回传的一切打成一个 tar.gz |
| `README_NVIDIA_PORT.md` | API 映射表、编译环境、已知风险（等主移植完成后补充细节）|

## 执行流程（四步，每步一个回传闸门）

```
第0步  环境探测      bash env_check.sh        → 回传 env_check_report.txt
第1步  编译          make 2>&1 | tee build.log → (失败才回传 build.log)
第2步  冒烟          bash run_phaseb_nv.sh smoke
                       完成后 bash collect_results.sh smoke
                                                → 回传 phaseb_nv_smoke_*.tar.gz
第3步  正式          （我确认 smoke 没问题后）bash run_phaseb_nv.sh formal
                       完成后 bash collect_results.sh formal
                                                → 回传 phaseb_nv_formal_*.tar.gz
```

**所有命令都在 `nvidia_port/` 目录下执行。**

## 我需要回传什么（按优先级）

1. **第 0 步的 `env_check_report.txt` 必须先发**——里面有 GPU 拓扑、P2P 实测、NCCL/NVSHMEM 版本。4090 消费级主板经常禁 GPU 间 P2P：如果 `can_access_peer` 全 0 或带宽塌到 <15 GB/s，NVSHMEM 会走 host proxy，整个实验解读方式都要调整，我需要先看到这个再决定要不要改参数。
2. **smoke 的 tar.gz**（用 `collect_results.sh` 打包，**失败也要发**——失败的 case 日志是我定位问题的唯一材料）。
3. formal 的 tar.gz（同上）。
4. 任何中途崩溃：把终端上最后 ~50 行复制给我即可（结果目录里的 stdout_stderr.log 已自动落盘，会被 collect 打包）。

## 铁律（和海光侧完全一致）

- 结果目录带时间戳，**绝不覆盖、绝不删除**；runner 有防覆盖锁，重复跑会自动开新时间戳目录。
- 失败的 case 也要保留（日志就在 case 目录里）。
- 平台名统一写 `RTX 4090 / sm_89 / 4 GPUs / PCIe`（引用海光时写 `K500SM_AI / gfx928 / 4 GPUs / PCIe`）。

## 实机不兼容怎么办

预期内。流程就是为这个设计的：
1. 你把 `env_check_report.txt`（环境类问题）或 `build.log` / 失败 case 的 `stdout_stderr.log`（编译/运行类问题）发回来；
2. 我在 DCU 侧改好代码/脚本重新给你（只发改动的文件）；
3. 你覆盖对应文件重跑——**结果根目录是新时间戳，旧的不动**。

常见的不兼容点我已经预判：NVSHMEM 版本差异（signal API 签名 2.x 内变过）、NCCL 版本差异（candidate 环境变量不生效）、MPI 与 NVSHMEM bootstrap 的组合、无 P2P 时的 transport 环境变量。都会在 README_NVIDIA_PORT.md 里列出对应开关。
